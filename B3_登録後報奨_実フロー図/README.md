# B3 登録後報奨 実フロー図

B3（登録後報奨）の処理を、仕様書の mermaid 図ではなく**プログラムが実際にたどる順序・分岐・出口**で描いたフローチャート。
JIS X 0121 の記号（端子・処理・判断・定義済み処理・ループ端・準備・データ・書類・表示・手作業・結合子）で手配置した。

- 根拠のコード：`kunonao/houshoukin` ブランチ `b3-registered-after`（`3c4b710`、2026-09-18）。
  `kunonao/houshoukin-project` の `共有用_報奨金算出_20260922/プログラム/` と同じ中身（改行コードだけ違う）。
- 仕様書の正本を置き換えるものではない。正本（改訂3a）の図と見比べるための「実際の動き」の図。

## 見方

| ファイル | 中身 |
|---|---|
| `B3_実フロー図.html` | 3枚の図と「仕様書の図との違い」「合成データでの確かめ」を1ページにまとめたもの。ブラウザで開く |
| `B3_実フロー図.pdf` | A3 縦・3ページ（印刷・配布用） |
| `svg/B3_実フロー図_{1_全体,2_グループ付番,3_グループ処理}.svg` | 図そのもの。Word・PowerPoint・ブラウザに貼れる |
| `png/…png` | 同じ図の画像（2倍の解像度） |
| `B3_実フロー図_mermaid.md` | 同じ内容の mermaid 版（ほかの LLM での照合用）。差分表・確認表の元もここ |

- 1/3 全体：bat の実行から結果ブックの保存まで。ファミリーのループと 3-0 入力ゲート。
- 2/3 グループ付番：3-1 真のH5 の確定と 3-2 報奨グループの付番（後回しのパスのループを含む）。
- 3/3 グループ処理：3-3〜3-8。報奨グループごとに①を1行作る（C0・C1・C3 とエラー脱出 C2）。
- ★＝仕様書の mermaid 図に描かれていない実際の処理、⚠＝技術的な不具合として処理全体を止める所。

## 作り直し方

```
python make_b3_flow.py            # svg/ と B3_実フロー図.html・B3_実フロー図_印刷用.html を作り直す（標準ライブラリだけ）
```

PNG と PDF は Chrome（Chromium）に描かせる。

```
chrome --headless --screenshot=png/B3_実フロー図_1_全体.png --window-size=1840,2242 --force-device-scale-factor=2 svg/B3_実フロー図_1_全体.svg
chrome --headless --no-pdf-header-footer --print-to-pdf=B3_実フロー図.pdf B3_実フロー図_印刷用.html
```

（`--window-size` は各 SVG の `width`・`height` に合わせる。2枚目 1880×2682、3枚目 1900×2171。）

- 図の配置は `make_b3_flow.py` の `page1()`〜`page3()` に座標で書いてある。コードが変わったらここを直して再実行する。
- 「仕様書の図との違い」「合成データでの確かめ」の表は `B3_実フロー図_mermaid.md` から HTML に取り込んでいる（表の中身は md の1か所だけ）。
- `検証/verify_b3_paths.py` は、実コードに合成データ13ファミリーを流して図の分岐を確かめるスクリプト
  （`python 検証/verify_b3_paths.py <プログラムのフォルダ>`。openpyxl が要る）。
