# DTP Software（仮称）

自分の小説本を同人誌印刷所 STARBOOKS に入稿するための、用途を絞った組版・入稿ツールを作るプロジェクト。

- 状態：2026-11-18 相談の段階。コードはまだない。
- 印刷所の入稿ルール：[docs/starbooks-spec.md](docs/starbooks-spec.md)

## 目的

- 原稿テキストから、印刷所が保証する形式（PDF/X-4）の入稿用PDFを作る。
- モリサワの有料フォントを使えるようにする。
- 縦書き（小説）と横書きの両方に対応する。

## 作らないもの

- InDesign のような汎用DTPソフト（画面上で自由にレイアウトする編集ソフト）。AIを総動員しても、確かめる作業が膨大になるので現実的ではない。

## 構成案

組版は既存のものを使い、自作の中心は「入稿用への仕上げとチェック」のツール1つにする。

| 部分 | 縦書き | 横書き |
|---|---|---|
| 組版 | Vivliostyle（または TeX） | LuaLaTeX + jlreq |
| 入稿用への仕上げとチェック | 共通ツール | 共通ツール |

共通ツールの役目：

- PDF/X-4 にする（出力条件の指定、仕上がり・塗り足しの範囲の指定、規格のメタデータ）。
- 本文の文字を K100（黒インクだけ）にする。
- 自動チェック：フォントがすべて埋め込まれているか、ページサイズ（塗り足し込み）、ページ数が偶数か、ノドの余白。

メモ：Vivliostyle の `--preflight press-ready` は PDF/X-1a 向け。STARBOOKS が保証するのは PDF/X-4 だけなので、X-4 への仕上げは自作する部分になる。

## 役割分担

| 担当 | やること |
|---|---|
| Claude Code | 設計、コードを書く、自動チェックを作る |
| ChatGPT など | 別の目で監査する（規格の読み違い、コードの穴） |
| 利用者 | 組版の見た目の判断。モリサワフォントの入ったPCで動かす |
| STARBOOKS | 1冊から刷れるので、試し刷り1冊を最終確認にする |

## 未確認のこと（PC側で確かめる）

1. Morisawa Fonts のアプリで有効にしたフォントが、Vivliostyle（ブラウザ経由）と TeX（ファイルを直接探す）から見えるか。
2. そのフォントをPDFに埋め込めるか（技術とライセンスの両面）。
3. PDF/X-4 の最終確認の方法。Acrobat Pro のプリフライトが使えるか、なければ試し刷りで確かめる。
4. 以前の入稿で何に苦戦したか。一太郎（JUST PDF）で書き出していた可能性があり、STARBOOKS は JUST PDF で文字が勝手にアウトライン化される不具合を挙げている。
